## 1. 产品概述

QQ Email MCP 是一个面向 AI 客户端的邮件上下文网关。AI 负责理解、判断、总结和生成，MCP 负责安全地连接 QQ 邮箱、查询邮件、规范化内容、提取附件并执行明确的邮件操作。

产品不把大模型能力封装进 MCP。搜索、分类、摘要、翻译和回复撰写由 MCP 客户端完成；MCP 提供高质量的上下文和可验证的动作。

## 2. 问题定义

AI 直接处理邮箱通常会遇到以下问题：

- MIME、Base64、RFC 2047 和 HTML 让原始邮件难以稳定理解。
- 邮箱文件夹、UID 和状态变化容易造成读错、改错或重复发送。
- 附件、长线程和邮件引用链会快速消耗上下文。
- 邮件内容可能包含提示注入，不能被视为可信指令。
- 发信和删除属于高影响操作，不能由模型静默执行。

本产品通过协议适配、上下文规范化和权限确认解决这些问题。

## 3. 产品目标

### 3.1 V1 目标

- 连接单个 QQ 邮箱账号并验证收发信配置。
- 浏览文件夹、邮件列表和未读邮件。
- 按关键字、发件人、日期和状态搜索邮件。
- 读取单封邮件和基础线程关系。
- 返回适合 AI 使用的正文、元数据和附件清单。
- 下载附件，并对常见文本类附件提供内容读取能力。
- 发送新邮件、回复、全部回复和转发。
- 标记已读、未读、星标、移动、归档和移入垃圾箱。
- 对高影响操作提供预览、确认、审计和失败保护。

### 3.2 成功标准

- 用户可以在 Codex 中完成一次真实邮件处理闭环，无需手工登录网页邮箱。
- 读取中文、HTML、多段 MIME 和带附件邮件时不出现乱码。
- AI 可以仅凭 `mail_get(mode="agent")` 的输出理解邮件主题、正文、线程和附件。
- 发信前始终能看见收件人、主题、正文和附件预览。
- 同一确认令牌重复调用不会造成重复发送；SMTP 超时后不自动重试，并明确提示发送状态未知。

## 4. 非目标

V1 明确不包含：

- 多账号管理
- 企业微信邮箱 Exmail
- QQ 网页 Cookie 或浏览器自动化
- 远程 HTTP MCP 和多租户
- IMAP IDLE 实时推送
- 本地全文索引和语义搜索
- OCR、日历自动调度、复杂规则引擎
- 永久删除
- 定时发送和营销群发

## 5. 目标用户与场景

### 5.1 目标用户

使用 AI 客户端处理个人 QQ 邮件的个人用户，尤其是需要频繁阅读、搜索、整理和回复邮件的知识工作者。

### 5.2 核心场景

1. 搜索最近未读邮件，并按重要性给出摘要。
2. 读取一个邮件线程，提取待办、日期和联系人。
3. 从邮件中下载合同、账单或表格附件并读取内容。
4. 根据邮件上下文起草回复，用户确认后发送。
5. 将已处理邮件标记已读、归档或移入垃圾箱。

## 6. 产品原则

- **协议优先**：使用官方 IMAP/SMTP，不以网页协议作为主数据通道。
- **上下文优先**：对 AI 返回规范化邮件，不要求模型理解原始 MIME。
- **动作原子化**：MCP 只提供可验证的邮件动作，不内置模型推理。
- **默认保守**：默认只读，写操作显式启用。
- **确认优先**：发送、回复和转发必须经过一次性确认；移入垃圾箱等修改操作必须显式开启 `permissions.update`，并在结果中返回逐条状态。
- **不可信内容**：邮件正文不能改变系统指令或触发新的工具调用。
- **单账号简单化**：不引入与单账号无关的账号抽象和租户复杂度。

## 7. 功能需求

### FR-01 配置与凭据

**优先级：P0**

系统必须支持配置 QQ 邮箱地址、IMAP/SMTP 授权码和附件目录。授权码必须保存到本地加密凭据文件，不写入项目配置或日志；开发环境可以使用环境变量回退。

验收标准：

- 缺失配置时返回可操作的错误提示。
- 授权码错误时返回稳定的认证错误，不泄露授权码。
- 更换授权码后无需修改代码。

### FR-02 连接状态

**优先级：P0**

`mail_status` 必须报告 IMAP 登录、SMTP 认证、文件夹访问和写权限状态。

验收标准：

- 可以区分 DNS、TLS、认证、权限和网络超时。
- 不返回授权码、Cookie 或完整协议调试日志。

### FR-03 文件夹

**优先级：P0**

系统必须通过 IMAP `LIST` 获取真实文件夹，并映射收件箱、已发送、草稿、垃圾箱等标准文件夹。

验收标准：

- 不硬编码中文文件夹名称。
- 支持 modified UTF-7 文件夹名称。
- 无法识别标准文件夹时返回空映射而不是猜测。

### FR-04 邮件列表

**优先级：P0**

`mail_list` 必须返回轻量邮件摘要和稳定游标，支持按文件夹、已读状态和数量筛选。

验收标准：

- 摘要包含主题、发件人、时间、已读状态、星标、附件标记和 `message_ref`。
- 分页不因新邮件到达而重复或跳过大范围结果。
- 不返回完整正文。

### FR-05 搜索

**优先级：P0**

`mail_search` 必须支持关键字、发件人、日期范围和未读状态组合查询。

验收标准：

- 优先使用服务端 IMAP 搜索。
- 返回与列表一致的摘要结构。
- 对不支持的服务端能力提供明确降级说明。

### FR-06 邮件读取

**优先级：P0**

`mail_get` 必须支持元数据、正文、线程和 AI 上下文四种模式。V1 的线程模式限定在当前文件夹内聚合。

验收标准：

- 正确解码文本、HTML、多段 MIME 和中文头部。
- HTML 默认清洗，移除脚本、表单和危险属性。
- 长正文返回截断标志和继续读取游标。
- 返回稳定的 `message_ref` 和可用的 `thread_ref`。

### FR-07 AI 上下文

**优先级：P0**

`mail_get(mode="agent")` 返回面向模型的规范化结构，包括发件人、收件人、时间、主题、正文、引用关系、链接、附件和不可信标记。

验收标准：

- 不返回原始 MIME、Base64 正文或无意义传输头。
- 默认去除重复签名和重复引用内容。
- 对邮件中的提示注入内容只编码为数据，不转成指令。
- 输出大小受 `max_chars` 控制。

### FR-08 附件

**优先级：P0**

系统必须返回附件清单并支持下载到配置的沙箱目录。

验收标准：

- 拒绝路径穿越、绝对路径和异常文件名。
- 文件重名时生成安全随机名。
- 默认限制单附件和总附件大小。
- 可执行文件只允许下载，不自动执行。

### FR-09 附件内容提取

**优先级：P0 / P1**

P0 支持 TXT、CSV、JSON、XML、HTML 和 PDF 文本提取。P1 支持 DOCX、XLSX 和 PPTX。

验收标准：

- 返回提取文本、字符数、截断状态和提取器类型。
- 提取失败时保留附件元数据并返回可理解错误。
- 压缩包 V1 不自动解压。

### FR-10 发送新邮件

**优先级：P0**

`mail_send(mode="new")` 必须支持收件人、抄送、密送、主题、正文和附件。

验收标准：

- 发送前生成预览和 `confirmation_token`。
- 确认令牌绑定发送内容并一次性使用。
- 自动生成合法的 `Message-ID` 和 `Date`。
- 超时后不自动重复发送。

### FR-11 回复与转发

**优先级：P0**

`mail_send` 必须支持回复、全部回复和转发，并正确设置线程头。

验收标准：

- 回复设置 `In-Reply-To` 和 `References`。
- 全部回复排除当前账号并遵循原始收件关系。
- 转发保留原邮件内容并允许附加新正文。

### FR-12 邮件管理

**优先级：P0**

`mail_update` 必须支持标记已读、标记未读、星标、取消星标、移动、归档和移入垃圾箱。

验收标准：

- 使用 `(folder, uidvalidity, uid)` 定位邮件。
- 移动支持 `UID MOVE`，不支持时使用安全回退。
- V1 不提供永久删除。

### FR-13 权限与确认

**优先级：P0**

系统必须支持只读、允许草稿、允许修改和允许发送四种权限层级。

验收标准：

- 只读模式拒绝所有写操作。
- 草稿属于低风险写入，需显式开启 `permissions.draft`（或 `permissions.update`）；草稿不发送邮件，也不需要确认令牌。
- 发送、回复和转发缺少确认时拒绝执行。
- 归档和移入垃圾箱必须依赖显式开启的修改权限，并且不接受目标文件夹改道。
- 每次发送确认显示目标、动作和关键内容摘要。

### FR-14 审计与错误

**优先级：P0**

系统必须生成脱敏审计记录，并返回稳定、可处理的错误结构。

验收标准：

- 记录时间、工具、动作、文件夹、UID、结果和错误码。
- 不记录邮件正文、附件内容、授权码和完整邮件地址列表。
- 错误结构包含 `code`、`message`、`retryable` 和可选 `details`。

## 8. 用户流程

### 8.1 首次配置

1. 用户开启 QQ 邮箱 IMAP/SMTP 并生成授权码。
2. 用户把邮箱地址写入配置，把授权码写入本地加密凭据文件。
3. 用户调用 `mail_status`。
4. 系统验证 IMAP、SMTP、文件夹和权限。

### 8.2 处理未读邮件

1. AI 调用 `mail_search` 或 `mail_list` 获取未读摘要。
2. AI 选择目标并调用 `mail_get(mode="agent")`。
3. AI 提取摘要、待办、日期和附件。
4. 用户决定回复、归档或标记状态。
5. AI 调用 `mail_send` 或 `mail_update`。

### 8.3 确认后发送

1. AI 调用 `mail_send`，请求预览和确认令牌。
2. 系统返回预览，不发送邮件。
3. 用户确认收件人、主题、正文和附件。
4. AI 使用确认令牌再次调用 `mail_send`。
5. 系统执行发送并返回结果。

## 9. 非功能需求

| 类别 | 要求 |
|---|---|
| 可靠性 | 只读网络错误可重试；发送由一次性确认令牌保护，超时后不自动重放；修改操作按消息返回独立结果 |
| 性能 | 本地工具调用普通操作 P95 小于 3 秒，发送取决于 SMTP |
| 安全 | 凭据隔离、最小权限、路径白名单、不可信内容隔离 |
| 隐私 | 默认不记录正文和附件，不上传数据到第三方服务 |
| 兼容性 | 支持 Codex，并尽量兼容标准 stdio MCP 客户端 |
| 可维护性 | 模块边界清晰，IMAP/SMTP/MIME 可独立测试 |
| 可观测性 | 结构化错误、脱敏日志、操作耗时和结果状态 |

## 10. 成功指标

- 真实 QQ 邮箱主流程成功率达到 99% 以上，排除外部服务故障。
- 中文邮件读取乱码率为 0。
- 发送确认机制覆盖率为 100%。
- 重复发送事故为 0。
- 附件路径逃逸测试全部通过。
- 单封普通文本邮件从请求到返回 AI 上下文小于 2 秒。

## 12. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| QQ IMAP 能力差异 | 搜索或移动行为不一致 | 启动时探测能力，提供安全回退 |
| SMTP 超时后状态未知 | 重复发送 | 一次性确认令牌禁止重放同一请求，超时后要求用户人工核对已发送文件夹再决定是否重发 |
| HTML 邮件含恶意内容 | 提示注入或隐私泄露 | 清洗 HTML，默认阻止远程资源 |
| 附件名和编码异常 | 路径穿越或乱码 | 统一规范化并限制沙箱路径 |
| 长线程超出上下文 | 信息遗漏 | 分层读取、引用去重、游标截断 |

## 13. 待确认事项

- 是否允许发送时自动保存到已发送文件夹。
- PDF 文本提取是否进入 M1，而不是 M3。
- 附件默认大小上限和沙箱目录。
- 是否允许 V1 直接访问远程图片，当前建议一律阻止。
