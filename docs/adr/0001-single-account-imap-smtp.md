# ADR 0001: 单账号 IMAP/SMTP 架构

| 字段 | 内容 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-09-21 |

## 背景

产品目标是让 AI 处理个人 QQ 邮箱中的邮件。首版需要可靠完成搜索、阅读、附件处理、发送和基础管理，同时避免引入与目标无关的复杂度。

## 决策

V1 采用单账号、本地 stdio、IMAP/SMTP 架构。

- 不实现多账号和账号路由。
- 不实现 QQ 网页 Cookie 或浏览器自动化。
- 不实现远程 HTTP MCP。
- 不实现数据库索引。
- 对 AI 返回规范化邮件上下文。

## 理由

- 单账号足以覆盖个人使用场景，并显著简化配置、凭据和连接管理。
- IMAP/SMTP 是邮箱的稳定协议通道，比网页协议更适合长期维护。
- stdio 不暴露网络端口，适合本地个人工具。
- 无数据库可以减少状态同步和隐私风险。

## 影响

正面影响：

- 更小的实现面和测试面。
- 凭据、连接和错误处理更容易控制。
- 后续可以在服务层外增加多账号，而不需要重写协议适配器。

负面影响：

- 无法同时处理多个邮箱。
- 不做本地索引时，大规模邮箱搜索依赖服务端 IMAP。
- 不提供实时推送，只能按需查询。

## 后续演进

如果出现明确的多账号需求，可以引入 `AccountContext`，为每个账号持有独立连接和服务实例。该演进不应进入 V1。
