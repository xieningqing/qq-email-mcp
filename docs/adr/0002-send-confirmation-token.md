# ADR 0002: 发送使用一次性确认令牌

| 字段 | 内容 |
|---|---|
| 状态 | Accepted |
| 日期 | 2026-09-21 |

## 背景

发信、回复和转发是不可逆的外部动作。模型可能因为误判收件人、正文或附件而触发错误发送，单纯依赖客户端 UI 确认不足以约束所有 MCP 客户端。

## 决策

`mail_send` 默认只生成预览和一次性 `confirmation_token`。令牌与规范化后的待发送内容绑定，并保存于内存，使用后立即失效。

客户端确认后，只回传 `confirmation_token`。服务端从令牌存储中取回原始待发送内容，不接受客户端在确认阶段修改正文、收件人或附件。

如果客户端拒绝确认、关闭确认流程或 elicitation 请求失败，服务端会立即撤销该令牌。令牌一旦消费或撤销，后续调用必须返回 `CONFIRMATION_INVALID`。

## 理由

- 避免“确认 A，发送 B”的时间差攻击。
- 防止模型在第二次调用中改写内容。
- 令牌一次性使用，降低重复发送风险。
- 服务端保存内容，客户端接口更简单。

## 影响

- 令牌默认十分钟过期。
- 服务进程重启后待确认内容丢失，需要重新生成预览。
- 不提供跨进程持久化的确认队列，这与单机单账号定位一致。
